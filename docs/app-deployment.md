# App Deployment Operations

The backend publishes generated applications to a filesystem directory. It never serves generated bytes through Spring MVC. The authenticated `/api/static/{codeGenType}_{appId}/` compatibility endpoint only redirects owners to an isolated preview URL. For local development, an optional JDK `HttpServer` serves previews and deployments on a separate port.

## Backend Configuration

| Property | Environment variable | Development default | Purpose |
| --- | --- | --- | --- |
| `app.deployment.root-dir` | `APP_DEPLOY_ROOT_DIR` | `tmp/code_deploy` | Filesystem root containing one directory per deploy key |
| `app.deployment.host` | `APP_DEPLOY_HOST` | `http://localhost:9332` | Public static origin used to build deployment URLs |
| `app.deployment.local-server.enabled` | `APP_DEPLOY_LOCAL_SERVER_ENABLED` | `true` | Enables the isolated local static listener |
| `app.deployment.local-server.bind-address` | `APP_DEPLOY_LOCAL_SERVER_BIND_ADDRESS` | `127.0.0.1` | Address used by the local listener |
| `app.deployment.local-server.port` | `APP_DEPLOY_LOCAL_SERVER_PORT` | `9332` | Port used by the local listener; `0` is intended for tests only |

Use a persistent volume for `root-dir` in production. It must be on a different, non-nested path from `tmp/code_output`. Staging, backup, and tombstone directories are created beside final deployment directories, so the whole deployment root must stay on one filesystem and be writable by the backend process.

The backend returns URLs in the form:

```text
http://localhost:9332/aB3x9Q/
```

## Generated Draft Preview

Generation preview and deployment are separate states. Successful generation publishes the latest complete draft to `tmp/code_output`, but it does not allocate a `deployKey`, update `deployedTime`, or replace an existing public deployment. `POST /api/app/deploy` remains the explicit publish operation.

The generation SSE stream exposes the draft only after every completion step succeeds. Content events retain the existing `{"d":"<chunk>"}` data shape. The preview provider copies the completed output into an ephemeral immutable snapshot under `tmp/code_preview` before the final named `done` event contains its time-limited bootstrap bearer URL and `expiresAt` value:

```text
event:done
data:{"previewUrl":"http://localhost:9332/preview/<token>/","expiresAt":1753405723000}
```

New frontend code should navigate an iframe or browser to `done.previewUrl` and allow redirects. This URL is a bootstrap credential, not a generated-content URL. After validating it, the isolated preview server sets an `HttpOnly`, `SameSite=Strict` cookie scoped to `/preview-content/{publicId}/`, then returns `302` or `303` to that token-free path. The browser loads `index.html` and relative assets from the immutable snapshot through the scoped cookie; generated JavaScript cannot read the cookie, and the bearer token does not remain in the content URL.

For compatibility, an authenticated owner may still open the exact legacy URL `/api/static/{codeGenType}_{appId}/`, where `codeGenType` is `html` or `multi_file` and `appId` is positive. That API endpoint never serves generated bytes: it validates the owner, creates a fresh bootstrap grant, and returns `307 Temporary Redirect` to `previewUrl` with `Cache-Control: no-store` and `Referrer-Policy: no-referrer`. The preview server then performs the cookie exchange described above. Malformed directory names, nested asset paths, and arbitrary `/api/static/**` requests are not static-resource mappings and remain errors.

Bootstrap tokens do not reveal the application id or generation type. They are issued only to the authenticated owner, expire automatically, and are invalidated after a later snapshot is successfully signed, application deletion, or backend restart. Each grant is bound to one immutable snapshot rather than the mutable `tmp/code_output/{codeGenType}_{appId}` directory. If regeneration fails, is cancelled, or cannot sign and publish its new preview snapshot, the stream emits no `done` and the previous token or preview cookie continues to show the previous snapshot. It must never begin serving partially updated or newly generated files through the old grant.

An owner that reloads the editor, has an expired token, or reconnects after a backend restart can request the current complete draft without regenerating it:

```http
POST /api/app/preview
Content-Type: application/json

{"appId": 2001}
```

The response contains a fresh bootstrap `previewUrl` and epoch-millisecond `expiresAt`. A successful signing rotates the application's prior preview access only after the new immutable snapshot is ready. Anonymous callers and other users cannot issue a token. Unknown, malformed, expired, and revoked bootstrap tokens, public ids, or preview cookies all return `404` from the isolated listener.

When the local listener is enabled, `app.deployment.host` must be an `http` origin without a path, query, fragment, or user information, and its effective port must equal `app.deployment.local-server.port`. For a specific bind address, the public hostname must resolve to that address. A wildcard bind such as `0.0.0.0` or `::` can use any resolvable public hostname with the same port. Startup fails on a mismatch so the deployment API cannot return an unreachable URL.

## Isolated Static Server

The local listener starts only after the primary Spring web server publishes its `WebServerInitializedEvent`. It is not started by mock-web-context tests and is not part of the backend servlet context.

Its request contract is deliberately narrow:

- only `GET` and `HEAD` are accepted; all other methods return `405` with `Allow: GET, HEAD`;
- `/{deployKey}` redirects to `/{deployKey}/`, and the trailing-slash URL serves `index.html`;
- `/preview/{token}/` is a bootstrap endpoint: it validates the bearer grant, sets an `HttpOnly`, `SameSite=Strict`, path-isolated preview cookie, and redirects with `302` or `303` to `/preview-content/{publicId}/` without putting the token in `Location`;
- `/preview-content/{publicId}/` and its relative assets serve only the immutable snapshot bound to that public id and require the matching path-scoped cookie;
- HTML, CSS, JavaScript, images, fonts, and common data assets receive deterministic MIME types;
- directories are never listed, and nested directory URLs are not treated as additional index pages;
- malformed keys, missing files, traversal attempts, encoded separators, hidden paths, temporary publication directories, and symbolic links return `404`;
- every response uses `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, and `Permissions-Policy: camera=(), microphone=(), geolocation=()`; deployment responses use `Content-Security-Policy: sandbox allow-scripts`, while preview responses additionally block network connections, forms, objects, frames, and base-URL changes;
- the sandbox does not grant `allow-same-origin`, `allow-forms`, or top-navigation privileges, and the server sends no credentialed CORS headers.

The listener binds to loopback by default. The separate port creates a distinct browser origin, while cookie scope still depends on cookie domain and path. The default `http://localhost:9332` preview origin is same-site with the default `http://localhost:5173` editor, so its `SameSite=Strict` preview cookie can be sent from an iframe. Custom environments must preserve that relationship: use a preview host that is same-site with the editor page, but keep it on a distinct origin through a separate port or dedicated subdomain. A cross-site preview host causes browsers to suppress the strict cookie in the iframe. Preview cookies must remain `HttpOnly`, `SameSite=Strict`, and restricted to their exact `/preview-content/{publicId}/` path. Keep backend session cookies scoped to `/api`, and never broaden their domain or path to cover preview or deployed content.

## Production Static Server

Disable the JDK listener when a production static server or CDN owns the public host:

```text
APP_DEPLOY_LOCAL_SERVER_ENABLED=false
APP_DEPLOY_ROOT_DIR=/var/lib/auto-code/deployments
APP_DEPLOY_HOST=https://sites.example.com
```

This configuration serves explicit deployments only. The current preview provider is implemented only by the local JDK listener. When it is disabled or unavailable, `POST /api/app/chat/gen/code` fails before invoking the AI provider so the backend does not incur generation cost for a stream that cannot satisfy the required `done.previewUrl` contract. `POST /api/app/preview` and the legacy preview redirect also fail instead of returning an unusable URL.

Production environments that need draft preview must implement an equivalent token-aware provider or gateway that performs the bootstrap-token validation, path-scoped cookie exchange, immutable-snapshot lookup, and revocation rules. The built-in JDK listener supports only the directly reachable HTTP origin contract described above and is intended for local development. A filesystem-only static server or CDN that merely serves `code_deploy` is sufficient for explicit deployments but is not a preview provider.

Configure the external static server with the deployment root as its document root and:

- resolve each `{deployKey}/` directory through `index.html`;
- serve `.html`, `.css`, and `.js` with their correct MIME types;
- disable directory listing;
- return `404` for missing keys and files;
- avoid long-lived caching for deployed files, because redeployment keeps stable URLs and filenames;
- never expose hidden staging, backup, or tombstone directories;
- reject symbolic links and path traversal beneath the deployment root;
- apply an equivalent sandboxing CSP and the other local-server security headers;
- use an origin outside the backend session-cookie scope.

Generated HTML and JavaScript are untrusted. Do not map the deployment root into the backend `/api` origin and do not configure backend session cookies with a domain or path that covers the static host. Prefer a dedicated hostname for production deployments.

## Database And Topology Checks

Before rollout, verify the real `app` table has `UNIQUE KEY uk_deployKey (deployKey)`. Re-running `sql/init.sql` does not add the index to an already existing table because it uses `CREATE TABLE IF NOT EXISTS`.

The current processing guard coordinates one JVM. Run a single deployment writer for a shared deployment root until distributed locking and shared-storage coordination are implemented. Database uniqueness still protects key assignment, but it does not serialize same-App directory replacement across multiple backend instances.

## Smoke Test

1. Generate an HTML App and a multi-file App to completion, then navigate to each `done.previewUrl` before deploying.
2. Confirm the bootstrap response sets an `HttpOnly`, `SameSite=Strict`, path-isolated cookie and redirects to `/preview-content/{publicId}/` without the bearer token in the final URL.
3. Confirm multi-file CSS and JavaScript load relative to the token-free content directory, the exact owner-authenticated legacy URL returns a `307` to the bootstrap URL, and the API origin never serves generated file content.
4. Force regeneration preview signing to fail; confirm no `done` is emitted and the prior token or cookie still serves the prior immutable snapshot.
5. Regenerate successfully; confirm prior preview access returns `404`, the new bootstrap flow serves the new snapshot, and any prior deployment still serves its old published snapshot.
6. Deploy each App and open the returned trailing-slash deployment URL.
7. Confirm unsupported methods and directory-listing attempts are rejected and the CSP does not contain `allow-same-origin` or `allow-forms`.
8. Restart the backend; confirm old bootstrap and content access return `404`, then request `POST /api/app/preview` as the owner and open the replacement bootstrap URL.
9. Disable the local listener; confirm generation fails before any AI provider call unless a token-aware preview provider is configured.
10. Delete each App; confirm its preview and deployment URLs are no longer served.
